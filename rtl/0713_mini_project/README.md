# RHYTHM BEAT - FPGA & PC 연동 핵심 수정 내용

이 문서는 카메라 인식 연동 및 실시간 판정 동작을 위해 수정된 핵심 내용입니다.

---

## 1. FPGA (보드) 수정 사항

### 📌 top.sv (최상위 모듈)
* **어디를**: 카메라 수직동기화 신호(`vsync/v_sync`) 및 `U_sender` 모듈의 키 입력 포트(`.btn`)
* **어떻게**: 
  * `assign w_cam_vsync = vsync;` 및 `assign v_sync = w_vga_sync;`로 신호 방향을 교정함.
  * `.btn` 포트에 `{region[1], btn[2] | region[2], btn[1] | region[3], btn[0] | region[0]}`을 매핑함.
* **왜**: 
  * 입력과 출력 핀 맵 방향이 거꾸로 되어 있어 게임 동작 클럭이 통째로 멈추던 치명적인 문제를 수정했습니다.
  * 보드의 물리 버튼 작동도 유지하면서, 카메라에 빨간색이 감지된 영역(`region`) 정보도 PC로 함께 전송되도록 묶어주어 PC 화면의 노트 레인이 정상 하이라이트(반짝임) 되게 만들었습니다.

### 📌 top_module.sv
* **어디를**: 게임 리셋 회로, 판정 신호 출력 포트 선언, `U_GAMERESULT` 인스턴스 맵핑
* **어떻게**:
  * 사용자의 임시 수정 시도 과정에서 발생했던 **`combd_data` 오타**를 `combo_data`로 교정함.
  * 누락되었던 탑 아웃풋 판정 포트(`perfect`, `good`, `miss`, `combo`, `fever`)와 `Rom_Sel_Reader` 호출 시 누락된 `.main_state` 매핑을 복구함.
  * 동기 신호 입력 경로에 **10us 공용 글리치 필터(디바운서)**를 전역 장착하고 `Note_Controller`, `line_count`, `GameResult`에 공통 연결함.
* **왜**: 
  * 식별자 오타 및 포트 누락으로 인해 Vivado 비트스트림 합성이 에러로 실패하여 옛날 버그 코드로 계속 돌아가던 문제를 원천 해결하고 성공적으로 컴파일할 수 있게 보정했습니다.
  * 카메라 감지 시 발생하는 UART 송신 전자기 노이즈가 `v_sync` 신호선에 침투(Crosstalk)하여 1초 만에 강제 종료를 유발하던 현상을 최상위에서 차단했습니다.

### 📌 MainController.sv
* **어디를**: 포트 선언부 및 내부 인스턴스 매핑
* **어떻게**: 판정 결과 신호 포트 및 내부 연결 와이어들을 추가함.
* **왜**: 보드 내부 판정기(`GameResult.sv`)가 내린 Perfect/Good/Miss 판정 결과를 UART 송신기로 흘려주기 위해 거쳐가는 통로 포트들을 복원했습니다.

### 📌 Rom_Sel_Reader.sv (곡 데이터 리더)
* **어디를**: 곡 정보 주소(`rom_addr`)가 1씩 증가하는 로직
* **어떻게**:
  * 사용자가 임시 테스트한 단일 어드레스 증가 코드에서 발생했던 **곡 주소 범위 초과(rom_addr 42) 한계 체크 누락** 및 **대기 상태에서의 주소 난치 버그**를 보완하여 복구함.
  * `note_done` 펄스가 켜지고 `main_state == 3'b011` 일 때만 정상적으로 주소가 넘어가도록 템포 FSM을 안전하게 맵핑함.
* **왜**: 곡이 진행되다가 롬 깊이(43개)를 넘어선 주소의 쓰레기 값을 읽어와 FSM이 강제 종료되거나 대기 중에 주소가 엉키는 현상을 해결하기 위함입니다.

### 📌 Note_Controller.sv
* **어디를**: 수직동기화 클럭 입력(`v_sync`) 처리
* **어떻게**: 개별 글리치 필터를 제거하고, `top_module.sv`가 공급하는 깨끗하게 정제된 공용 `v_sync_clean` 신호를 엣지 샘플링에 사용하도록 매핑함.
* **왜**: 동기화 신호의 중복 필터링 설계를 지양하고, 시스템 아키텍처 상 탑 모듈에서 필터링된 공용 신호를 깨끗하게 수신하여 오동작을 예방하기 위함입니다.

### 📌 sender.sv (UART 송신기)
* **어디를**: UART 데이터 전송 트리거(`event_trigger`) 및 데이터 수집부 (`DATA` 상태)
* **어떻게**:
  * 펄스형 판정 신호를 전송 주기 동안 기억해두는 홀드 레지스터(`perfect_held` 등)를 신설하여 전송함.
  * 물리 버튼(`btn`) 입력은 누르는 그 순간(상승 엣지)에만 송신 트리거가 켜지도록 변경함.
* **왜**:
  * 1클락(10ns) 짜리 아주 짧은 판정 펄스가 상태 머신 딜레이 때문에 패킷이 조립되기도 전에 사라지던 데이터 유실 문제를 해결했습니다. (수정 후 Perfect/Good/Miss가 PC 화면에 씹히지 않고 즉시 뜸)
  * 물리 버튼을 꾹 누르고 있으면 카메라 감지 결과 전송이 통째로 먹통(락)이 되던 통신 충돌 현상을 고쳤습니다.

## 2. Python (PC 게임) 수정 사항

### 📌 main.py
* **어디를**: 화면 전환 제어 함수인 `_switch_screen` 및 UART 로그 출력문
* **어떻게**: 
  * 특정 화면 제약을 풀고, 화면이 전환될 때마다 해당 화면에 초기화 함수가 있다면 항상 `reset()` 이 자동 호출되도록 변경함.
  * 딕셔너리 수신 로그를 출력할 때 발생하던 16진수 포맷 오류를 일반 텍스트 출력으로 교체함.
* **왜**: 
  * 게임이 끝난 뒤 결과 창(`ResultScreen`)으로 넘어갈 때 점수(`score`) 속성이 설정되지 않아 `AttributeError` 예외와 함께 파이썬이 강제 종료되던 크래시 현상을 완전히 고쳤습니다.
  * 수신 로그 오류로 인해 프로그램이 예외 에러로 튕기는 버그를 해결했습니다.

### 📌 screens/game_screen.py
* **어디를**: 곡의 노트 파일(.mem)을 읽어오는 경로 설정부
* **어떻게**: 프로젝트 루트 폴더를 탐색하는 상대 경로 탐색 깊이 수정.
* **왜**: 파이썬이 곡 정보 메모리 파일을 찾지 못해 곡 선택 직후 게임 화면으로 넘어가지 못하고 튕겨 나가던 폴더 경로 에러를 수정했습니다.

### 📌 screens/result_screen.py
* **어디를**: 파티클(빛 입자) 효과 클래스의 초기화 부분
* **어떻게**: `self.current_alpha = 0` 기본 속성 선언 추가.
* **왜**: 노래가 끝난 뒤 결과 화면에 진입할 때 특정 속성이 존재하지 않는다며 화면이 멈춰버리던 버그를 조치했습니다.

### 📌 config.py
* **어디를**: 게임 플레이 파라미터 중 `NOTE_SPEED` (노트 낙하 시간)
* **어떻게**: `NOTE_SPEED = 3.0` 에서 `NOTE_SPEED = 2.333` 으로 변경함.
* **왜**: FPGA 보드 내부에서 노트가 위에서 판정선까지 떨어지는 물리적인 시간(140프레임 = 2.333초)과 PC 파이썬 게임 상의 낙하 시간(3.0초) 사이에 약 0.7초의 큰 시차가 있어, 화면을 보고 정확히 쳐도 보드에선 이미 지나가버려 Miss가 뜨던 싱크 불일치를 완벽하게 고쳤습니다.
