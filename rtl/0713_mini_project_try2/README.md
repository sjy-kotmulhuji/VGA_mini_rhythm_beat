# RHYTHM BEAT - FPGA & PC 연동 핵심 수정 내용

이 문서는 카메라 인식 연동 및 실시간 판정 동작을 위해 수정된 핵심 내용입니다.

---

## 1. FPGA (보드) 수정 사항

### 📌 top.sv (최상위 모듈)
* **어디를**: 카메라 수직동기화 신호(`vsync/v_sync`), `U_sender` 모듈의 키 입력 포트(`.btn`) 및 판정 입력 포트(`.perfect`, `.good`, `.miss`), 신규 `U_VGAcam` 인스턴스 핀 매핑
* **어떻게**: 
  * `assign w_cam_vsync = vsync;` 및 `assign v_sync = w_vga_sync;`로 신호 방향을 교정함.
  * `.btn` 포트에 들어가는 신호를 `w_state == 3'b011` (GAME_CONT) 상태 여부에 따라 분기시키는 **상태별 버튼/카메라 신호 분리 결합 회로(`w_uart_btn`)**를 설계하여 매핑함. (대기 화면 등에서는 오직 물리 버튼 `btn` 신호만 통과시킴)
  * `w_perfect`, `w_good`, `w_miss` 신호에 `w_state == 3'b011` 일 때만 전송되도록 **상태 기반 앤드 마스킹 게이트(w_*_masked)**를 설계하여 `U_sender`에 우회 연결함.
  * **[카메라 업데이트 연동]** 신설된 내부 와이어 `w_lane`, `w_lcnt0~3` 을 선언하고, `U_MainController` 가 출력하는 실시간 노트 정보들을 최신 `U_VGAcam` 모듈의 신규 입력 포트(`.note_x`, `.note_y0`, `.note_y1`, `.note_y2`, `.note_y3`)에 다이렉트로 연결함.
* **왜**: 
  * 입력과 출력 핀 맵 방향이 거꾸로 되어 있어 게임 동작 클럭이 통째로 멈추던 치명적인 문제를 수정했습니다.
  * 곡 선택이나 시작 대기 화면에서 **카메라에 빨간색이 감지될 때 버튼 입력으로 오인되어 곡이 멋대로 휙휙 넘어가거나 게임이 지 혼자 시작되는 현상을 원천 방지**하고, 오직 실제 플레이 상황에서만 카메라 입력을 타격 라인 하이라이트에 사용하도록 통제했습니다.
  * 보드가 부팅되거나 대기 상태일 때 초기 신호 불안정 및 가짜 엣지로 인해 튀는 **파워온 글리치성 Miss/Perfect 가짜 판정 신호가 UART를 타고 날아가 PC 화면을 연달아 오작동/종료시키는 치명적인 통신 버그를 원천 차단**했습니다.
  * 최신 카메라 모듈이 VGA 화면에 낙하하는 노트를 직접 투사(그리기)할 수 있도록 물리적인 Y좌표와 레인 신호 통로를 개통해 주었습니다.

### 📌 Basys-3-Master.xdc (제약 파일)
* **어디를**: 물리 버튼(`btn[0~3]`), UART 송신(`tx`) 및 VGA 포트 핀 설정
* **어떻게**: 
  * 기존 비활성화(주석 처리)되어 있던 물리 버튼 핀 포트(`btn[0]`, `btn[1]`, `btn[2]`, `btn[3]`) 및 시리얼 통신 송신 핀(`tx`) 매핑 주석을 제거하여 전역 활성화함.
  * 기존에 임시로 잘못 켜져 있던 `region[0~3]` LED 매핑 주석을 다시 주석 처리함.
  * 사용자 요청에 따라 VGA 관련 핀 매핑(`port_red`, `port_green`, `port_blue`, `h_sync`, `v_sync`)을 제외한 나머지 모든 업데이트 내역을 동기화함.
* **왜**: 물리 버튼 입력 신호와 UART 통신 송신 신호가 실제 Basys3 핀에 정상 연동되도록 활성화하고, 중복 매핑으로 인한 합성 에러를 방지하기 위함입니다.

### 📌 top_module.sv
* **어디를**: 게임 리셋 회로, 판정 신호 출력 포트 선언, `U_GAMERESULT` 인스턴스 맵핑, `v_sync` 입력단, 신규 출력 포트(`o_lcnt0~3`) 선언
* **어떻게**:
  * 사용자의 롤백으로 인해 유실되었던 **10us 공용 글리치 필터(디바운서) 회로**를 최종 재복구하여 정제 신호(`v_sync_clean`)를 각 하위 모듈에 일괄 재맵핑함.
  * `combd_data` 오타를 `combo_data`로 교정하고, 누락된 `perfect`/`good`/`miss` 등의 탑 포트 선언과 `Rom_Sel_Reader` 호출 시 누락되었던 `.main_state` 매핑을 최종 복원함.
  * **[카메라 업데이트 연동]** 최신 `VGAcam` 모듈의 실시간 노트 렌더링에 필요한 슬롯별 Y좌표(`lcnt0`, `lcnt1`, `lcnt2`, `lcnt3`)를 모듈 출력 포트(`o_lcnt0`, `o_lcnt1`, `o_lcnt2`, `o_lcnt3`)로 새로 뚫어 바인딩함.
  * 이전 사용자 수정 시도는 주석으로 기록을 남겨 백업 보존함.
* **왜**: 
  * 카메라 감지에 의한 UART 패킷 고속 송신 시 발생하는 전기적 통신 노이즈가 `v_sync`에 타고 흘러들어 프레임 진행 엣지가 남발되고 게임이 조기 종료되던 하드웨어 버그를 완벽하게 차단하기 위함입니다.
  * 문법 에러 및 포트 불일치로 비트스트림 합성이 깨지던 현상을 완벽히 해결했습니다.
  * 최신 카메라 모듈이 요구하는 실시간 노트 Y좌표 데이터를 상위 모듈로 전파하기 위함입니다.

### 📌 MainController.sv
* **어디를**: 포트 선언부 및 내부 인스턴스 매핑
* **어떻게**: 판정 결과 신호 포트, 내부 연결 와이어, 그리고 신규 노트 Y좌표 출력 통과 포트(`o_lcnt0~3`)를 추가함.
* **왜**: 
  * 보드 내부 판정기(`GameResult.sv`)가 내린 Perfect/Good/Miss 판정 결과를 UART 송신기로 흘려주기 위해 거쳐가는 통로 포트들을 복원했습니다.
  * `top_game` 내부에서 전파된 노트의 Y좌표 값들을 최상위 탑 모듈로 흘려주기 위한 브리지 포트를 생성했습니다.

### 📌 GameResult.sv (판정기)
* **어디를**: 포트 선언부 및 모듈 최하단
* **어떻게**:
  * **[노트 렌더링 개선]** 사용자 제안에 따라 `GameResult` 포트에 `o_lane` 출력을 신설하고, 실시간 낙하 중인 슬롯들의 위치(`pos0~3`)와 Y좌표(`lcnt0~3`)를 조합(OR)한 연산문을 추가하여 밖으로 전파함.
* **왜**: 실시간 하락 중인 노트들의 정확한 가로 레인 비트맵 상태를 VGA 렌더링 모듈로 매 클록 공급하기 위해 모듈화 경계를 개선했습니다.

### 📌 score.sv (점수 계산기)
* **어디를**: 콤보 계산식 및 보너스 가산 대입문
* **어떻게**: 콤보 식 대입 방식을 넌블로킹(`combo_reg <= ...`)에서 **블로킹(`combo_reg = ...`)** 대입 방식으로 변경하고 기존 코드는 주석 백업함.
* **왜**: 넌블로킹 대입(`<=`)은 클록의 다음 사이클에서 값이 갱신되므로, `combo_done`이 활성화된 그 클럭에 아래의 조건문이 이전 콤보 값인 `0`을 참고하여 점수가 전혀 누적되지 않던 클럭 타이밍 미스 버그를 해결하기 위함입니다.

### 📌 Rom_Sel_Reader.sv (곡 데이터 리더)
* **어디를**: 곡 정보 주소(`rom_addr`)가 1씩 증가하는 로직
* **어떻게**:
  * 사용자가 임시 테스트한 단일 어드레스 증가 코드에서 발생했던 **곡 주소 범위 초과(rom_addr 42) 한계 체크 누락** 및 **대기 상태에서의 주소 난치 버그**를 보완하여 복구함.
  * `note_done` 펄스가 켜지고 `main_state == 3'b011` 일 때만 정상적으로 주소가 넘어가도록 템포 FSM을 안전하게 맵핑함.
* **왜**: 곡이 진행되다가 롬 깊이(43개)를 넘어선 주소의 쓰레기 값을 읽어와 FSM이 강제 종료되거나 대기 중에 주소가 엉키는 현상을 해결하기 위함입니다.

### 📌 Note_Controller.sv
* **어디를**: 수직동기화 클럭 입력(`v_sync`) 처리
* **어떻게**: 개별 글리치 필터를 제거하고, `top_module.sv`가 공급하는 깨끗하게 정제된 공용 `v_sync_clean` 신호를 엣지 샘플링에 사용하도록 매핑함.
* **왜**: 동기화 신호의 중복 필터링 설계를 지양하고, 시스템 아키텍처 상 탑 모듈에서 필터링된 공용 신호를 깨끗하게 수신하여 오동작을 예방하기 위함입니다.

### 📌 frameController.sv (VGA 제어 모듈)
* **어디를**: `Filter_NOTE` 모듈의 각 슬롯별 그리기 필터 조건식
* **어떻게**: `y1_disp`, `y2_disp`, `y3_disp` 조건 판단 식에서 0번 Y좌표(`note_y0`)가 잘못 공통 중복으로 들어가 있던 오타를 각각 슬롯 번호에 대응되는 Y좌표(`note_y1`, `note_y2`, `note_y3`)로 올바르게 정정함.
* **왜**: 0번 외 다른 슬롯의 노트가 떨어질 때, 엉뚱하게 0번 슬롯의 Y좌표 상태에 지배받아 렌더링에 간섭하거나 누락되던 픽셀 충돌 버그를 수정하기 위함입니다.

### 📌 sender.sv (UART 송신기)
* **어디를**: UART 데이터 전송 트리거(`event_trigger`), 데이터 수집부 (`DATA` 상태), `register_file` 모듈 정의부
* **어떻게**:
  * 펄스형 판정 신호를 전송 주기 동안 기억해두는 홀드 레지스터(`perfect_held` 등)를 신설하여 전송함.
  * 물리 버튼(`btn`) 입력은 누르는 그 순간(상승 엣지)에만 송신 트리거가 켜지도록 변경함.
  * **[합성 에러 해결]** 하위 모듈인 `register_file` 정의 시, 모듈 이름과 내부 RAM 배열 변수명(`register_file`)이 동일하여 발생한 식별자 충돌 버그를 해결하기 위해 내부 변수명을 **`mem`**으로 전면 교정함.
* **왜**:
  * 1클락(10ns) 짜리 아주 짧은 판정 펄스가 상태 머신 딜레이 때문에 패킷이 조립되기도 전에 사라지던 데이터 유실 문제를 해결했습니다. (수정 후 Perfect/Good/Miss가 PC 화면에 씹히지 않고 즉시 뜸)
  * 물리 버튼을 꾹 누르고 있으면 카메라 감지 결과 전송이 통째로 먹통(락)이 되던 통신 충돌 현상을 고쳤습니다.
  * Vivado에서 `failed synthesizing module register_file` 합성 에러가 발생하며 컴파일이 통째로 터지던 RTL Elaboration 크래시 현상을 원천 수정했습니다.

### 📌 OV7670setting.mem (카메라 설정 데이터 롬)
* **어디를**: 레지스터 데이터 파일 전반 (60개 주소 설정부)
* **어떻게**: 14팀의 `OV7670_Config_I2C.sv` 에 등록되어 있던 60개의 모션 캡처 및 노이즈 필터링 최적화 레지스터 테이블(밝기 `@3b 5587` 및 윈도우 스케일링 설정 등)을 100% 동일하게 전체 이식함.
* **왜**: 주변 실내 조명 잡음 차단 성능 및 RGB 채널의 빨간색 검출 감도를 극대화하여 마스킹 오작동을 근본적으로 제거하기 위함입니다.

## 2. Python (PC 게임) 수정 사항

### 📌 uart_handler.py (UART 데이터 수신 파서)
* **어디를**: `_parse_packet` 함수 내의 버튼(Up, Down, Right, Left) 비트 추출 영역
* **어떻게**: Basys3 실물 핀 맵 순서(`btn[0]=Up`, `btn[1]=Left`, `btn[2]=Right`, `btn[3]=Down`)에 부합하도록 비트 쉬프트 마스킹 대입문을 올바르게 재조열함.
* **왜**: 하드웨어에서 인코딩되어 송신되는 버튼 비트 위치와 파이썬 측의 디코딩 비트 위치가 반대로 뒤집혀 엇갈려 있어, 물리 버튼을 누르면 다른 엉뚱한 방향키가 입력되던 키 맵 꼬임 문제를 해결하기 위함입니다.

### 📌 main.py
* **어디를**: 화면 전환 제어 함수인 `_switch_screen` 및 UART 로그 출력문
* **어떻게**: 
  * 특정 화면 제약을 풀고, 화면이 전환될 때마다 해당 화면에 초기화 함수가 있다면 항상 `reset()` 이 자동 호출되도록 변경함.
  * 딕셔너리 수신 로그를 출력할 때 발생하던 16진수 포맷 오류를 일반 텍스트 출력으로 교체함.
* **왜**: 
  * 게임이 끝난 뒤 결과 창(`ResultScreen`)으로 넘어갈 때 점수(`score`) 속성이 설정되지 않아 `AttributeError` 예외와 함께 파이썬이 강제 종료되던 크래시 현상을 완전히 고쳤습니다.
  * 수신 로그 오류로 인해 프로그램이 예외 에러로 튕기는 버그를 해결했습니다.

### 📌 screens/game_screen.py
* **어디를**: 곡의 노트 파일(.mem)을 읽어오는 경로 설정부
* **어떻게**: 프로젝트 루트 폴더를 탐색하는 상대 경로 탐색 깊이 수정.
* **왜**: 파이썬이 곡 정보 메모리 파일을 찾지 못해 곡 선택 직후 게임 화면으로 넘어가지 못하고 튕겨 나가던 폴더 경로 에러를 수정했습니다.

### 📌 screens/result_screen.py
* **어디를**: 파티클(빛 입자) 효과 클래스의 초기화 부분
* **어떻게**: `self.current_alpha = 0` 기본 속성 선언 추가.
* **왜**: 노래가 끝난 뒤 결과 화면에 진입할 때 특정 속성이 존재하지 않는다며 화면이 멈춰버리던 버그를 조치했습니다.

### 📌 config.py
* **어디를**: 게임 플레이 파라미터 중 `NOTE_SPEED` (노트 낙하 시간)
* **어떻게**: `NOTE_SPEED = 3.0` 에서 `NOTE_SPEED = 2.333` 으로 변경함.
* **왜**: FPGA 보드 내부에서 노트가 위에서 판정선까지 떨어지는 물리적인 시간(140프레임 = 2.333초)과 PC 파이썬 게임 상의 낙하 시간(3.0초) 사이에 약 0.7초의 큰 시차가 있어, 화면을 보고 정확히 쳐도 보드에선 이미 지나가버려 Miss가 뜨던 싱크 불일치를 완벽하게 고쳤습니다.
